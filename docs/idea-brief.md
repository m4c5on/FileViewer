# Idea brief — file-viewer

## 1. Raw idea

file viewer, хочу переглядати MD, mermaid в приємному форматі. можливістю редагувати MD файл. це мені потрібно для перегляду документації по проекту. мені не подобається як відображається стилістика в MD файлах - занадто "шумно", а я люблю коли все візуально охайно і чисто. щось подібне вже є в cursor додатку, це я звідти надихнувся, побачив у співробітника в єкрані. хочу переглядати MD файли у приємному форматі, а не з шумом розмітки, кривих таблиць і так далі.

## 2. Problem

Перегляд `.md`-документації проєкту в наявних інструментах (наприклад, у IDE на кшталт Cursor) виглядає «шумно»: видима розмітка, криві таблиці, відсутність охайного, чистого візуального стилю. Потрібен окремий, зосереджений спосіб читати і швидко правити документацію без ваги повноцінного IDE.

## 3. Users

Власник ідеї (розробник) — основний користувач, який регулярно читає й редагує `.md`-документацію своїх проєктів. Друга черга — команда/інші розробники, що читають ту саму документацію; під їхній workflow, стилі й конвенції продукт спеціально не підлаштовується.

## 4. Why now

Прямого дедлайну чи інциденту немає — тригер естетичний і продуктивнісний: побачив у колеги на екрані подібний охайний перегляд у Cursor і захотів окремий, легший інструмент саме під читання/редагування проєктної документації, без шуму IDE.

## 5. Out of scope

- Інші формати, крім `.md` + базовий перегляд текстових файлів — щоб не розмивати фокус v1 попри назву «FileViewer».
- Редагування mermaid-діаграм (візуальне перетягування вузлів/стрілок) — v1 лише рендерить/показує діаграму.
- Налаштовувані теми/стилі перегляду — v1 має один опінійований, фіксований вигляд.
- Повна гарантія round-trip без втрат для будь-якого markdown (вкладені списки, front matter, сирий HTML) — підтримується обмежене підмножина, решта — fallback у raw-режим.
- Інтеграція в macOS Quick Look/Finder — розглянута як альтернативний кут, не обрана для v1.

## 6. Risks

- WYSIWYG-редагування ризикує зіпсувати складні markdown-конструкції (вкладені списки, front matter, сирі HTML-вставки) при збереженні назад у `.md` — знижено рішенням обмежити підтримуваний підмножин у v1, складне лишається у raw/fallback.
- Припущення «швидкість і фокус без IDE-шуму» — головна цінність проти Cursor; якщо користувачі й команда не відчують різниці на практиці, диференціація зникає.
- Повний обсяг одразу (браузер + перегляд + редагування) в одній v1 — більший інженерний ризик і час розробки, ніж вужчий read-only перший реліз.
- Один фіксований опінійований вигляд може не влаштувати частину команди, яка звикла до інших стилів/конвенцій.

## 7. Recommendation

Будувати окремий, легкий macOS-додаток (macOS 26+, новий проєкт) із власним браузером папки/проєкту, чистим і охайним переглядом `.md` та mermaid-діаграм (лише рендер) в одному фіксованому опінійованому вигляді, і WYSIWYG-редагуванням обмеженого підмножини markdown — з fallback у raw-режим для складних конструкцій. Базовий перегляд інших текстових файлів — щоб виправдати назву FileViewer, без розширення фокусу. Головна перевага над відкриттям Cursor — швидкість і фокус без ваги IDE.

## 8. Open questions

- Наскільки прийнятний ризик round-trip fidelity для реальних документів команди — потребує перевірки на живих `.md`-файлах проєкту (власник ідеї).
- Чи команда справді відчує різницю «швидкість/фокус без IDE-шуму» на практиці, чи піде далі користуватись Cursor (власник ідеї, після першого релізу).
